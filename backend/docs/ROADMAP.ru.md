## 0. Где мы сейчас (ветка `develop`)

Работает и проверено на реальных данных:

- Поиск по имени (SIMBAD + собственное движение) или координатам; 5 целей челленджа в один клик.
- Живой конвейер для любой точки неба: IRSA SIA (DR1 + QR3) → быстрые частичные вырезки
  (~120 КБ на кадр) → облачная копия NASA как запасной путь при ошибках 503 → вычитание ZODI,
  маски флагов, билинейное выравнивание → стеки по визитам.
- Плеер: стеки визитов, все кадры, разность, **Compare 2 dates** (рядом, мигание A↔B, B−A),
  кольцо предсказанного положения, ссылки с состоянием, прогресс для новых точек.
- Движение совпадает с каталогом: Barnard's Star — 10,3″ ожидается, 9,3″ измерено за год;
  WISE 0855 и Epsilon Indi B согласуются. Измерение Epsilon Indi B с проверкой по Gaia из `dev`
  (4,29″ против 4,68″ по каталогу) влито как скрипты, в интерфейсе пока не показано.
- Не сделано: публичный деплой, сравнение «на равных» по длине волны, глубокие поля,
  цветная картинка, спектры, движущиеся объекты.

## 1. Правила

1. `develop` всегда должен запускаться. Работаем в коротких ветках, сливаем, когда работает.
2. **Сначала один демо-сценарий**: открыл ссылку → мигает Barnard's Star → Compare → Difference.
   Всё остальное — бонус и не должно ломать этот путь.
3. У каждой новой фичи есть время «делаем / бросаем». Если к нему не работает — переносим
   в «после хакатона» и останавливаемся.
4. Заморозка кода в **09:30**. После — только багфиксы и сдача.

## 2. Что изменено относительно v5.0 и почему

| Пункт v5.0 | Решение | Почему |
|---|---|---|
| AWS us-east-1 рядом с зеркалом S3 | **Оставляем, главный приоритет** | Измеренное узкое место: из облака ~2,5 МБ на кадр; из дома медленно, внутри us-east-1 должно быть быстро. Хранилище публичное, ключи не нужны |
| Коллекции `_deep` | **Оставляем, 15 мин** | `spherex_dr1_deep`, `spherex_qr3_deep` дают больше кадров у полюсов эклиптики (например, R Dra) |
| Поправки потока для QR2 | Убираем | QR2 больше не ищется; мы берём только DR1 + QR3 |
| Полоса гелия 1,083 мкм и «shuttle glow» | **Оставляем, по желанию** | Оба явления реальны и описаны (проверено): атмосферная эмиссия He I даёт полосы в диапазоне 1, а IRSA для DR1/QR3 даёт шаблоны: гелиевый (диапазоны 1–2), авроральный (1) и «shuttle glow» (5, свечение самого аппарата на низкой орбите). Вычитает ли их уже конвейер NASA — не сказано, проверить до вычитания. Моё прежнее «убираем» было ошибкой |
| Карта `CWAVE` 2040×2040 | Заменяем | Используем таблицу `WCS-WAVE` детектора (лежит в `app/wavetables/`); проверено, что она одинакова для всех кадров и релизов |
| Флаги `DICHROIC`, `EARLY/LATE TRANSIENT` | **Решено** | Реальные имена из заголовка FITS: `DICHROIC` есть (бит 7; по документации ненулевой только в диапазонах 3–4). Флаг `TRANSIENT` один (бит 0), EARLY/LATE нет. Полный список в разделе 5 |
| Маски перекрёстных наводок, буфер «призраков» на 5 кадров | **Заменяем флагами** | Моделировать не нужно: конвейер NASA уже помечает по пикселям `CROSSTALK`, `PERSIST`, `GHOST`, `GHOST_FPA`, `GHOST_EXT`, `STREAK`, `SNOWBALL`, `BLOOM`, `HALO`. Добавить их в необязательную «чистую» маску и в слой Pro-режима (1 ч) |
| `reproject_adaptive` | Оставляем как есть | Билинейное выравнивание уже сохраняет положение до долей пикселя; движение проверено |
| Цветная картинка: синий 0,75–1,62, зелёный 2,42–3,82, красный 3,83–5,0 мкм | **Оставляем, исправлено** | В v5.0 пропущен D3 (1,6–2,4 мкм). Теперь: синий = D1+D2, зелёный = D3+D4, красный = D5+D6 |
| «D1+D4, D2+D5, D3+D6 снимают одновременно» | **Верно (проверено по данным)** | В 1963 из 2014 экспозиций одну точку неба покрывают именно эти пары, других сочетаний нет. Полезно для цветной картинки: кадры пары сняты в одно время. Но разные детекторы — разные длины волн, так что их сумма даёт широкополосную картинку, а не более глубокую в одном диапазоне |
| Оптимальная разность ZOGY | Убираем | 1–2 дня. Наша простая разность уже показывает пару «чёрное-белое» |
| Aladin Lite v3 + AllWISE/unWISE + Gaia | Бонус | Только если останется время после основного |
| Решение траекторий с OBSGEO, 5-параметровая астрометрия | Убираем | Исследовательский проект |
| Фотометрия ePSF / по следу / по кривой роста, Lomb–Scargle, переключение единиц | Заменяем | **Простой спектр на лету**: апертурная фотометрия на уже скачанных кадрах (у каждого кадра известна длина волны в точке цели) |
| Сверка с CatWISE, карты пыли | Убираем | После хакатона |
| Режимы Explorer / Pro | **Оставляем** | Совпадает с целью «понятно без наших объяснений» |
| Комета 3I/ATLAS, околоземный астероид | **Пробуем, с ограничением по времени** | См. блок F. Сначала комета: у околоземного астероида большой параллакс с низкой орбиты |
| Предобработка на RTX 4070 | Убираем | Работа упирается в сеть, а не в видеокарту |
| Глубокое поле у северного полюса эклиптики | Оставляем как пресет | Дёшево после подключения `_deep` |

## 3. Блоки работ

Оценки — на одного человека. «Готово» значит проверено в браузере на реальных данных.

### A. Публичный деплой на AWS us-east-1 — главный приоритет

- EC2 в **us-east-1** (тот же регион, что `nasa-irsa-spherex`), например t3.medium,
  Ubuntu, диск 30 ГБ под кэш.
- `git clone` ветки `develop`, Python venv, `npm run build`, `uvicorn` как служба systemd,
  обратный прокси с HTTPS (Caddy). Без домена подойдёт `<ip>.sslip.io` — Caddy с ним работает.
- Скопировать или пересчитать готовые цели (`python -m scripts.precompute`).
- Замерить на сервере: время на кадр через вырезку и через облако. Если облако там быстрое,
  поставить `SPHEREX_SOURCE=cloud` — тогда ошибок 503 от IRSA не будет вовсе.
- Готово: ссылка открывается без входа с телефона; 5 целей мгновенно; новая точка < 60 с.
- 2–3 ч. **Делаем / бросаем: 23:00.**

### B. Быстрые улучшения конвейера

1. Добавить `spherex_dr1_deep`, `spherex_qr3_deep` в `COLLECTIONS` (15 мин).
2. Посчитать 5 целей × D1–D6 заранее, чтобы смена длины волны была мгновенной (фоном, 30–60 мин).
3. **Сравнение «на равных» по длине волны** в Compare: складывать каждый визит только из кадров
   в общем для A и B диапазоне длин волн и показывать этот диапазон. Нужно для переменных звёзд
   (RW Aur, R Dra) и для критерия Validity. 2 ч.

### C. Сценарий для судей и режимы Explorer / Pro

- Стартовая страница: Barnard's Star, Compare, мигание, одно предложение пояснения.
- Короткая легенда: оранжевое кольцо — прогноз по каталогу; белое/чёрное на разности —
  стало ярче/тусклее; белые ядра — насыщение.
- Explorer (по умолчанию): поиск, 5 целей, пресеты длин волн, воспроизведение, Compare.
  Pro: детекторы, поле зрения, контраст, все кадры, флаги, ссылки на FITS.
- Метка качества на визите (хорошо / частично / плохо) по покрытию, числу кадров, насыщению.
- 2–3 ч.

### D. Цветная картинка (Creativity)
