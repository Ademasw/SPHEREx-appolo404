# Отчёт об интеграции front и backend

Дата: 14 ноября 2026.

## Результат и границы

Интерфейс из `front/front` перенесён в `backend/frontend`, включая страницы, стили, изображения, анимации, глобус, проигрыватель, сравнение и панели. Все изменения находятся внутри `backend`. Исходная папка `front` не изменялась. Существующие файлы Python в `app`, алгоритмы, маршруты, очереди, кэширование, научная обработка и исходные серверные тесты не изменялись.

Это интеграция с сохранением возможностей сервера, а не реализация новых научных алгоритмов. Требование реализовать абсолютно все предполагаемые возможности фронтенда несовместимо с запретом изменять обработку: Kelsall, регулируемая сила вычитания, отключаемая маска, реальные глобусные тайлы и SSE/WS в исходном сервере отсутствуют. Эти ограничения явно обозначены ниже; выполнение этого остатка требует отдельного решения. Не выдаём демонстрационные данные за реальные наблюдения.

## Что работает

- Главная страница, фон, анимации, курсор, вращение/масштаб глобуса, выбор области и переход к её координатам.
- Ввод координат или названия объекта. Пресеты используют идентификаторы каталога вместо неподтверждённых координат из макета; разрешением координат занимается существующий сервер.
- Запрос реальной последовательности через `/api/sequence`, обработка HTTP 202, ожидание результата раз в 1,5 секунды, отмена ожидания при смене запроса и размонтировании. Серверная задача после отмены браузера продолжает работу по прежним правилам.
- Ошибки API показываются пользователю. Пустой запрос не запускает обработку. Предыдущие изображения убираются при новом запросе. Лимит ожидания — 20 минут на детектор.
- Проигрывание, пауза, покадровое переключение, скорость, FPS, шкала времени и клавиатура работают на URL реальных кадров.
- Выбор D1–D6; режим all последовательно получает все шесть детекторов и объединяет кадры по времени. Если один детектор завершится ошибкой, отображается ошибка всего запроса, частичный набор не выдаётся за полный.
- FOV выбирается из 3, 6, 12 угловых минут — точного набора 0.05, 0.1, 0.2 градуса сервера.
- Сравнение использует ближайшие к выбранным датам доступные визиты, при отсутствии визитов — кадры. Пустые даты означают первый/последний. Подписи настраиваются; реальные даты сохраняются. При совпадении выбранного наблюдения показано предупреждение. В all сравнивается первый детектор D1, что явно указано в метаданных.
- Overview показывает реальные координаты, FOV, число кадров, шаги обработки и научные предупреждения.
- Старый интерфейс сохранён без изменения исходного JSX/CSS в `frontend/src/legacy`, доступен по `/legacy.html` и ссылке Advanced archive viewer. Его сравнение, разности, дополнительные визуальные настройки и сведения сохраняются.

## Ограничения

- Kelsall, независимое включение/выключение ZODI, процент силы и переключение маски не реализованы: сервер неизменно выполняет IMAGE−ZODI, вычитание медианы и обработку FLAGS. Это прямо отражено в панели и заблокированных контролах.
- Глобус использует исходные демонстрационные изображения и координаты. Это не карта покрытия SPHEREx и не вычисление положения снимков по наземным обсерваториям. Переход выбирает указанную демонстрационную область и запрашивает её реальные данные.
- SSE, WebSocket и серверная генерация видео отсутствуют; основной рабочий режим — последовательность PNG.
- Поле зрения произвольного размера и произвольные новые эпохи требуют расширения сервера.
- Реальная загрузка архива зависит от IRSA/SIMBAD и может быть длительной. Полный прогон внешнего архива не выполнялся; проверки ниже локальные.

## Оставшееся решение

Для буквального выполнения «весь функционал» необходима реализация научных фильтров и реальных данных глобуса, которых не было на сервере. На текущем этапе эти функции не заявляются работающими. Вопрос об отдельном новом модуле обработки задан пользователю; до явного разрешения запрет менять логику бэкенда соблюдён.
